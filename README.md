# Face-Recognition
Face Recognition project for Computer Vision class at University of Notre Dame


# Part 1
  For my semester project, I have chosen to work on Face Recognition. I think that this is a very interesting subject and will give me experience in solving a classic computer vision problem. The goal of my project will be to correctly recognize images of me from other people. Ideally, I would like this program to work on live video–detecting faces, drawing a box around them, and recognizing my face in real time–but I will first get it to work on images.
  
  To implement a solution to this problem, I will need to write a program that uses a face detection method, to find faces in images, and one of the image feature descriptors, to recognize my face from other faces. To train my model, I will first need to acquire a dataset of images of people, facing forward and with various lighting conditions. The description of this particular semester project suggests BioID as a resource to find these images. There are also many other datasets of faces that I will look into. Whichever dataset I use, I will have to consider using pictures for training, testing, and the final demonstration. I will also need to take a lot of pictures of my face to train the model on recognizing my face specifically. I plan to use 20 images of my face for training, 10 images for testing, and then 10 images for the final presentation of performance, all of which will be taken with various lighting and poses. Hopefully, I won’t need these last 10 images, as I will try to use a live camera feed to demonstrate my project’s final performance. 
  
  The first task the system needs to perform is face detection, which is identifying any faces present in the image or video frame. For this detection phase, the description of this project suggests using the Viola-Jones algorithm, and, from what I can tell from my research, this seems like a good choice due to its speed and accuracy. This method uses a Haar Feature-based cascade classifier, which operates by scanning the image for areas that resemble facial features, like the eyes, nose, or mouth. The system will then use this information to draw a bounding box around the face in the image. After the face is detected, the system will need to perform facial recognition, where it will determine whether the face belongs to me or someone else. For this recognition phase, I will need to use a feature extraction method. Currently, I am planning to use Local Binary Patterns (LBP), which was also suggested by the description. This is a feature descriptor that is able to capture patterns in a face by analyzing variations in the pixel intensities. LBP will then create a feature vector for each face, which it will compare against the stored descriptors that represent the trained faces, which will allow it to classify the detected face as mine or not. There are many factors that could make this process difficult for the system, like variations in lighting conditions, head poses, or expressions. LBP seems like it is particularly resistant to changes especially in lighting, which will be a benefit for this project.
  
  Ultimately, this project will provide me with experience in object detection, feature extraction, and image classification, which are all important computer vision problems, and I’m really excited to implement facial recognition.

# Part 2
  For my project, I used the [BioID Face Database](https://www.bioid.com/face-database/) dataset. This dataset consists of 1521 grayscale images from 23 different test subjects, and each image is in the visible light spectrum and has a resolution of 384x286 pixels. Because the goal of the project is to detect and recognize my face, I added 68 pictures of myself. I wrote a script to crop the images of my face to the same aspect ratio as the dataset and make them grayscale, to match the other images. These new images bring the total number of images to 1,589 of 24 different subjects, which is about 66 images of each subject. These images are taken with different facial expressions, camera positions, lighting conditions, and backgrounds to ensure diversity in the training data. To split up the data between training and validation, I decided it would be beneficial to keep a couple subjects only in the validation stage, to make sure that the model is generalizable to people it's never seen before. I also added pictures of myself to both the training and validation datasets, to train the model on my face and also test it. For the unknown test set, I will add more images of my face, along with images of my friends to test how the model does on recognizing my face among others. I also plan to test my model on video from the webcam, and see if it can detect and recognize my face in realtime.

# Part 3

  My instructor gave me the advice to use either MediaPipe or MTCNN for the face detection step of this project, instead of the older Viola-Jones algorithm I had proposed in Part 1 above. Choosing between these two, I decided to use MediaPipe for face detection, as it is quicker and more efficient, even if it's not always as accurate as MTCNN. My end goal for the project is to use a live video stream from the webcam, and so I prioritized the faster algorithm, which also happened to be easier to use.

  Again, based on instructor suggestion, I decided to use a Convolutional Neural Network for feature extraction and classification instead of the earlier proposed LBP. The CNN takes as the input a 200x200 image in 3 channels, and has only 2 outputs for classifying the face detected as mine or not. This method was a lot simpler than using LBP and allows for a lot more flexibility in training. CNNs are very good at capturing patterns in images and are also fairly robust to changes in lighting or expression, so I thought that using one would be a good replacement for LBP.

  As I wrote in Part 2, I planned to include images of subjects in the validation data set that had not been seen in the training data. I thought that I would be able to do this with the dataset that I had acquired from BioID, but I realized there was no way to distinguish which of these files corresponded to which subject. Instead, I added some new images of my friends and family to include in the validation data set, along with images of myself. I then only used the BioID images in the training dataset. 

  The only preprocessing I have implemented so far is resizing the images to fit the input of the CNN. I didn't choose to rotate the images or blur them or do any preprocessing like that, even though I know that those are techniques that can be used when training a neural network on images. I felt that since any video of my face which I plan on testing on would always be pretty regular, I would train the model on just the regular images. However, before the next part of this project is due, I might go back and try rotating the pictures if I add more pictures of myself so that the model will work even if my face is turned sideways or rotated slightly.

  As described in Part 2 above, the images from the BioID dataset are in black and white and at a certain resolution. I wrote a script to convert any images of me or my friends that I added for training and validation to these same dimensions. The training script (`closed_train.py`) first loads these images, and then runs them through the MediaPipe algorithm for face detection. This algorithm locates the face and creates a bounding box around it. The training script takes this bounding box location, converts it into actual pixels in the image, and then returns just the pixels found in the area of the face. These face images are then run through preprocessing, where they are resized to 200x200 images, which are the input dimensions for the neural network. The training script does these steps for all 3 datasets (my face, the BioID dataset, and my friends' faces) and then separates these datasets into training and validation sets. The script next builds the CNN model, which is pretty simple. It has an input shape of (200, 200, 3), to take in the resized 200x200 face images in 3 channels. Once the model is built, it is trained on the training dataset, consisting of my face and faces from the BioID Face Database, and validated using the validation set, consisting of my face and my friends' faces. The model is then output and saved to a file to be used for testing.

# Part 4
  By the end of Part 3, I had a closed set facial detection and recognition model trained and working pretty well. Because of this, I was given a challenge by my instructor to change my recognition system from closed set to open set, to be able to train it once and then verify the face of any individual instead of just my own. 

  To accomplish this, I first modified my training script, now `open_train.py`, by removing the last layer of my Convolutional Neural Network after training. This is the layer that classifies the output to one of multiple known classes, in this case, either my face or not my face. To make this open set classification, instead of classifying the output, the model now produces an embedding or feature vector of the face detected. The idea of this is that, after training, the model will be able to generate embeddings for a set of known faces, and then in testing can compare the generated embeddings of the test faces to those of the known faces. For this project, I used cosine distance as the metric to determine the similarity between the embedding of a new face and the embedding of a known face because it is effective at evaluating the similarity in high-dimensional vectors. Because of this, the model and the project no longer has a classifier, and uses the cosine similarity of the embeddings to recognize faces. The only change I made to the actual training of the model was to include more images from the BioID face dataset in the training set, as I decided it was more important for the model to see more faces than to have a biased classification when the goal is now to generate face embeddings and not classify them. Testing this change proved that it did help the open set testing of this model.

  Even though the results of the classification training aren't a very good indicator of the open set performance from the generated embeddings, the model was able to achieve 99% training accuracy with a 70% validation accuracy. This might be an indication of slight overfitting from the disproportionate amounts of data, but I don't think that should impact the performance of the embeddings generated by the model. 

  I then changed the testing script `open_test.py` in a few ways. First, I added a function to generate embeddings of known faces. All the faces that should be recognized by the model need to be placed in the `Known_Faces` folder, and this function will then generate embeddings of these faces and store them in a dictionary which maps the name of the person to the embedding of their face. I then added a function to compare face embeddings to these known faces, using the cosine similarity of the embeddings. I changed the video facial recognition function to use this new verification function and also added a similar function that tests the facial recognition model on images instead of just videos.

  As a side note, I renamed all the files for the closed set model to start with `closed` and named all the files for this part of the project starting with `open`. 

  I first tested this new open set model on the same video as before.   In terms of future improvements, I think the biggest change I could make is to train my model in a way that is more beneficial for open set face recognition. Because I started this project with closed set classification, my model is currently being trained by classifying labeled images and then popping off the last classification layer to generate embeddings instead. While I'm sure that this does encourage the model to learn something about the face represented by the image, and hold some meaningful information in the embedding, it's not designed to be good for open set classification. To improve the project, I could switch to a training method such as triplet loss or contrastive loss that helps the model generate better embeddings for faces. I actually did try to switch to triplet loss training, which can be seen in the file `triplet_open_train.py`, and spent a long time trying to get it to work. Triplet loss training works by giving the model three images, two of the same person and one of a different person. The model then uses a loss function which compares the anchor image to the other two, and encourages the embedding to be more similar to the embedding of the image of the same person and more different from the embedding of the image of the other person. I spent hours trying to get this triplet loss to work, and wasn't able to come up with a viable model before the deadline for this part of the project. I think that this could be a major improvement to the project because the model will be trained to generate better embeddings for faces, which will allow it to distinguish better between faces. With that being said, this might be too big of an improvement to complete before the end of the project, and my model still does relatively well with the classification training that I am currently doing, but I know that this would help. I think before the final testing I will try to improve the model's performance by continuing to try different training parameters, amounts of data, and so on to try to achieve a better open set testing result.
